# 設計筆記：協定細節、CDC推導、除錯歷程

## 一、通訊協定設計

協定參考 NEC 紅外線遙控的概念自行設計，以**低電位（LOW）的長度**來區分位元 0 與位元 1。

| 符號 | 波形（HIGH / LOW，單位為 TX 時脈週期） | 意義 |
|------|------|------|
| Start  | HIGH 100, LOW 50 | 訊框起始 |
| Logic 0 | HIGH 10, LOW 10 | 位元 0 |
| Logic 1 | HIGH 10, LOW 30 | 位元 1 |
| End | HIGH 10, idle | 訊框結束 |

- 位元 0 與位元 1 的 **HIGH 長度相同**，差別只在 **LOW 的長度**——這是本協定的核心設計，讓接收端只需量測低電位持續時間即可判斷位元值。
- 資料以 **MSB first** 傳送。

### TX 編碼器

採 6 狀態 FSM（IDLE / START_HIGH / START_LOW / DATA_HIGH / DATA_LOW / END_HIGH）。`signal` 僅在各 `*_HIGH` 狀態拉高。位元索引（bit_index）在進入 DATA 階段時初始化，於 `DATA_LOW → DATA_HIGH` 的轉換點遞減，確保 MSB 先送。

### RX 解碼器

- **兩級同步器**：對非同步進來的 `signal` 連打兩級正反器（`s1 <= signal; s2 <= s1;`），後續邏輯一律使用 `s2`，避免亞穩態傳播。
- **邊緣偵測**：以 `s2` 與其前一拍 `prev` 比較，偵測上升／下降緣。
- **6 狀態 FSM**：依序量測 Start、StartLow、各位元的 HIGH/LOW 長度。位元值由 LOW 段的計數值落在哪個區間決定。

## 二、雙時脈跨時脈域（CDC）設計

這是本專題技術上最核心、也最超出基礎範圍的部分。

### 為什麼要做、怎麼做

單一時脈下，TX 與 RX 永遠對齊，跨域問題不會出現。為了製造**真正的**跨時脈域情境，本設計用 **MMCM（Clocking Wizard IP）**產生兩個時脈：

- `clk_tx` = **120 MHz**（TX 端）
- `clk_rx` = **80 MHz**（RX 端）

兩者比例為 **1.5 倍（非整數）**，刻意讓兩個時脈域在相位上互不相關——這正是跨時脈域問題會發生的條件。

### MMCM 啟動保護

```verilog
wire sys_rst = rst | ~locked;
```

`locked` 是 MMCM 鎖定完成的旗標。把它與手動 `rst` 做 OR，可確保在 MMCM 尚未穩定輸出時，全系統保持在 reset 狀態，避免用到還沒鎖定的時脈。

### 門檻值的重新推導

換到雙時脈後，原本的計數門檻**不能直接沿用**，因為 RX 是用**自己的時脈**在數數：

```
RX_count = 脈衝實際時間 ÷ RX 時脈週期
         = TX_count × (RX_freq / TX_freq)
         = TX_count × (80 / 120)
         = TX_count × 0.667
```

| 符號 | TX 端計數 | 換算後 RX 端計數 |
|------|-----------|------------------|
| Start | 100 | ≈ 66 |
| StartLow | 50 | ≈ 33 |
| Logic 0 | 10 | ≈ 7 |
| Logic 1 | 30 | ≈ 20 |

實作上門檻採**區間**判斷，以容忍時脈抖動（jitter）。

### CDC 安全性驗證

執行 `report_cdc` 後：

```
clk_out1_clk_wiz_0 → clk_out2_clk_wiz_0   Safely Timed   Endpoints=1   Safe=1
```

**為什麼這能證明 CDC 是真的、而且是安全的？** 亞穩態是**機率性**的——只有在訊號變化恰好落在接收正反器的setup/hold違例區內才會發生。兩個非整數倍、互不相關的時脈讓這種「邊緣對撞」必然會週期性出現；兩級同步器給第一級正反器一整個時脈週期去把可能的亞穩態收斂掉，使輸出在被使用前已穩定。

## 三、系統整合架構

頂層設計重點在於**把「模式編號」與「模式行為」分開處理**：

- **狀態指示（status_led）**：4顆LED以one-hot顯示目前模式，單純對`rx_data`做case mux
- **模式行為**：因驅動不同實體裝置，拆成三組獨立輸出mux（一般LED / RGB LED / 七段顯示器）

## 四、開發與除錯歷程

模擬正確、上板卻出錯，是本專題花最多時間、也學到最多的階段：

1. **RX 切換不了模式（END_LOW 卡死）**
   `END_LOW` 狀態原本寫死回自己，導致一個訊框結束後永遠出不來。修正為偵測到下一個Start邊緣時轉回`START_HIGH`。

2. **資料被綜合最佳化掉**
   資料更新區塊混用了阻塞（`=`）與非阻塞（`<=`）賦值，導致綜合工具判定暫存器無用而優化掉。統一為`<=`後解決。

3. **跑馬燈看起來像恆亮**
   計數門檻一開始設成`26'd3`，每步只隔3個時脈，肉眼看起來就是全亮。改成`26'd25000000`（0.25秒）後恢復正常。**教訓**：LED「恆亮」十之八九是計數器太快，不是燈壞。

4. **七段顯示是16進位不是10進位**
   `3×5=15`顯示為`0F`，因直接把二進位值送進七段。若要顯示十進位需另加BCD轉換（除10取餘，或double-dabble）。

5. **燒錄flash認錯型號**
   Vivado預設`s25fl032p`，實際板載為`mx25l3273f`，燒錄時Vivado會自動偵測並更正。
